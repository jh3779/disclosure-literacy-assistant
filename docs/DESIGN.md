## Context

개인투자자는 두 갈래의 정보 비대칭에 노출돼 있다: (1) 커뮤니티에 도는 테마주 루머가 실제
공시로 뒷받침되는지 모르고, (2) 실제 공시를 읽어도 상투적 IR 화법이 무엇을 의미하는지
모른다. 두 문제 모두 "**공시 텍스트 하나를 놓고, 그 뒤에 뭐가 있(었)는지 찾아준다**"는
동일한 과제이며, 대상 범위만 다르다 — 전자는 **특정 회사**의 공시가 **특정 주장**을
뒷받침하는지(개별 사실 대조), 후자는 **표현 패턴 전체**를 놓고 과거 통계적으로 무엇을
의미했는지(집계 통계)를 다룬다.

**시스템은 투자 판단을 절대 내리지 않는 심판이다.** 매수/매도 추천, 목표가, 등급·신호등을
일절 출력하지 않고 "공시에 실제로 뭐라고 쓰여 있는가 / 과거 패턴이 통계적으로 어땠는가"
까지만 다룬다 — 자본시장법상 유사투자자문업(불특정 다수 대상 특정 금융투자상품 투자판단
자문)을 피하기 위한 최우선 설계 제약이다.

## 확정 파라미터

| 항목 | 결정 |
| --- | --- |
| 데이터 | DART OpenAPI(원문 zip/XML, 재무정보 API), KIND(자율공시), 공매도·지분공시 — 전부 무료·즉시 발급 확인됨 |
| LLM | provider 스왑(`disclosure_lit/llm.py::complete` — 이전 프로젝트 narrative_qa의 것을 옮겨 옴) — openai/anthropic/gemini |
| 임베딩 | 미확정 — Phase 1에서 결정 |
| 스코프 | 코스피·코스닥 상장사 (비상장·코넥스 등은 제외) |
| 규제 방어선 | 사실 나열·통계까지만, 매수/매도 추천·목표가·등급·신호등 금지 |

## 아키텍처 (레이어)

```text
L5  평가 (횡단)        eval/ — 팩트체크 gold set·화법 클러스터 유의성
L4  데모 UI            demo/app.py — 입력창 하나, 시스템이 팩트체크/화법통계 자동 분기
L3  통합 리포트        report/card.py — L2a 결과에 L2b를 자동 주석으로 결합
L2b 화법통계 엔진      dictionary/{cluster,stats}.py — 상투구 클러스터링 + 사후 이벤트 통계
L2a 팩트체크 엔진      factcheck/{claim,verify}.py — 클레임 추출 + claim verification
L1  검색               retrieval/{company_index,phrase_index}.py — 종목별 검색 + 화법 클러스터 인덱스
L0  수집               dart/{client,ingest}.py — DART 원문·재무정보 수집·정규화
```

### 핵심 기능 흐름

1. **입력창 하나** — 루머 문장이든 공시 문장이든 아무거나 붙여넣는다
2. 시스템이 입력을 분류: 특정 종목에 대한 주장(claim)인지, 일반적 화법 문구인지 판단
3. **L2a 팩트체크**: 종목이 특정되면 DART 전문검색으로 해당 종목 공시와 대조 → 사실 나열
   (긍정/부정 동일 비중, 등급·신호등 없음)
4. **L2b 화법통계 주석**: 팩트체크 결과에 포함된 공시 원문에 알려진 상투구 패턴이 있으면
   자동으로 "이 표현, 과거 N건 중 M건이 X로 이어짐" 통계를 카드에 주석으로 첨부. 문구만
   단독 검색하는 진입점도 별도 제공
5. 근거 공시 원문 링크 첨부 — 최종 판단은 항상 사용자 몫

### claim verification (L2a)

일반 QA가 아니라 **"주장 → 근거 검색 → 대조"** 구조다. 이전 프로젝트 narrative_qa
(`qa/chain.py`)의 guard(groundedness 체크) 패턴을 재사용한다 — "루머 문장이 실제 공시
사실로 뒷받침되는가"를 groundedness 체크처럼 구현한다.

### 상투구 클러스터링 + 사후 이벤트 라벨링 (L2b)

순수 QA가 아니라 "표현 클러스터링 + 사후 이벤트 라벨링" 파이프라인이다. 과거 공시
텍스트에서 유사 상투구를 임베딩 유사도로 클러스터링하고, 각 클러스터에 대해 "그 이후
N개월 내 실제 발생한 후속 이벤트"(유상증자·인력감축 관련 후속 공시 등)를 라벨링한다.
검색 시점에는 입력 문장 → 클러스터 매칭 → 사전 계산된 통계 반환(매 요청마다 LLM을
호출하지 않는 캐시 조회 방식). **이 라벨링이 팀의 핵심 구현 작업**이다.

> 2026-09-17 정정: 이 절이 원래 narrative_qa의 gold set 수동 검수 작업에 빗대어 "자동
> 초안 + 전원 수동 검수"라고 적어뒀었는데, 실제 구현(A12, `scripts/label_post_events.py`)은
> `normalize_form_type()` 분류 + 시간창(3개월) 조인만으로 전량 자동 라벨링한다 — 수동
> 검수 단계는 없고, 그게 의도한 설계다.

## Phase 및 마일스톤

### Phase 1 — 기반 구축 (공통)

- **A(이승노)** 주도: DART API 키 발급, 원문 수집·정규화, 서식별 청킹, 종목코드 인덱싱
- **B(김가빈)·C(우지훈)**: L2a/L2b 출력 스키마(인터페이스 계약) 합의 — 이후 병렬 작업의
  전제 조건. `disclosure_lit/factcheck/verify.py::FactCheckResult`,
  `disclosure_lit/dictionary/stats.py::ClusterStats`에 초안이 잡혀 있다.
- **완료 기준**: 종목 하나 기준 최근 공시 검색 가능, 출력 스키마 문서화 완료

### Phase 2 — 핵심 엔진 병렬 개발

- **A**: Phase 1 완료 즉시 상투구 클러스터링 + 사후 이벤트 라벨링 착수(전체 일정 중 가장
  오래 걸리는 작업이라 최대한 앞당겨 시작)
- **B**: L2a claim verification 엔진 구현 + 과거 루머 사례 20~30건 gold set 수집·검수
- **C**: L2b 클러스터 매칭 검색 로직 skeleton + 데모 UI 와이어프레임
- **완료 기준**: 각자 엔진 단위 테스트 통과, gold set 20건 이상·클러스터 라벨 20개 이상 확보

### Phase 3 — 통합

- **C** 주도: L2a·L2b 산출물을 L3 통합 리포트 카드로 조립, L4 데모 화면 완성
- **A·B**: 통합 과정에서 나오는 데이터/로직 버그 픽스 지원
- **완료 기준**: 엔드투엔드 데모 동작 — 루머 입력 → 팩트체크 + (해당 시) 화법 통계 카드 출력

### Phase 4 — 평가 및 마무리

- 전원: 평가 지표 측정(정밀도·재현율, 클러스터 유의성), 규제 방어선 최종 재점검, 발표자료
  정리
- **완료 기준**: 평가 결과표 완성, 팀 리뷰 통과, 정식 강사 배포 양식 기획서로 재작성

## 성공 지표 (초안)

- 팩트체크: gold set 대비 정밀도·재현율 각 80% 이상
- 화법통계: 표본 20건 이상인 클러스터 15개 이상 확보
- 데모: 루머 입력 → 결과 카드 출력까지 응답시간 10초 이내(발표 데모 기준)

> 코드에서 옮겨 오거나 참고한 것의 기록이다.

| 재사용 | 신규 |

## 경쟁 서비스 비교 (2026-09-09~10 WebSearch/WebFetch 검증)

- **공시줍줍**(비즈워치 뉴스레터): 기자가 매일 수작업으로 공시를 선별·해설하는 편집형
  서비스. 자동화된 셀프서비스 도구가 아니라는 점에서 차별화됨
- **한경 유레카**: "공시 분석으로 투자할 가치가 있는 종목 발굴" — 방향이 반대(종목 발굴 vs
  검증/해설)라 성격이 다름
- "루머 입력 → 팩트체크" 또는 "문장 입력 → 화법 통계"를 자동화된 셀프서비스로 제공하는
  직접 경쟁 서비스는 특정하지 못함(존재하지 않는다는 증명은 아니므로 재검증 권장)
