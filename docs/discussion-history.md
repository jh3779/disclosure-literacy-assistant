## 읽기 전에

- **요약본이다.** 원문(이슈·PR 본문, 리뷰, 코멘트)을 그대로 옮긴 것이 아니다. 비공개 저장소에서
  AI 에이전트가 원문을 읽고 요약했으며, 사람이 전수 대조한 것은 아니다. 수치·함수명·파일명은 원문 표기를
  따랐다.
- **번호는 비공개 저장소 기준이다.** `#N`은 이 저장소가 아니라 이전 개발 저장소의 이슈·PR 번호이므로
  링크가 걸려 있지 않다. 이 저장소의 이력은 공개용 단일 스냅샷 커밋 하나뿐이다.
- **일부는 의도적으로 뺐다.** 개인 연락처, 로컬 경로, 공시 서명란의 제3자 실명, 제3자 저작물의 출처 같은
  공개에 적합하지 않은 내용은 서술에서 제외했다.
- **`원문 불분명`**은 입력된 원문에서 후속 반영이나 결과를 확인하지 못했다는 뜻이다. 반영되지 않았다는 뜻이
  아니다.
- 사람은 GitHub id로만 적었다: `powercodingman`(A, DART 파이프라인), `9abin`(B, L2a 팩트체크),
  `jh3779`(C, L2b·UI·평가). 의견 차이는 안(案) 단위로 서술했다.
- 기준 설계는 [DESIGN.md](DESIGN.md), 화면 계약은 [03_screen_contract.md](03_screen_contract.md)를 본다.
  이 문서는 그 결정에 이른 과정만 다룬다.

### #4·#5·#7·#9·#10·#11 초기 주제 후보(review-coach, 도메인 RAG, 주차규정봇) 탐색과 폐기 (모두 CLOSED, 2026-09-07 ~ 09-09)

배경은 팀 편성 직후 프로젝트 주제를 정하기 위한 후보 문서화였다. #4는 외부 리서치 메모를 review-coach PRD와 대조한 트리아지 메모로, Self-RAG류 자가판단·RAG 개인화는 적용 가능, GitHub Search Tool(프레임워크 이원화)·Graph RAG·fedRAG 등은 배제 권장으로 분류했고 "팀이 채택하지 않으면 병합하지 말고 닫아도 된다"고 명시했다. #7은 약국 재고(실시간 재고 API 부재로 반려)·응급실(공식 앱 E-gen이 동일 기능 제공)을 거쳐 11개 도메인을 톱다운(6개 중 1개 생존)·바텀업(5개 중 4개 생존)으로 조사했고, 같은 날 #5 브랜치로 병합되어 #5가 두 트랙(review-coach / 도메인 RAG)의 통합 비교 메뉴가 됐다. #5 본문에는 재검증 과정이 남아 있다. review-coach는 Korbit과 겹치고 CodeRabbit·Greptile도 근거 기반 리뷰를 이미 제공하며, 도메인 RAG 1위였던 상가 임대료·법적 리스크는 AskLaw와 거의 같아 강등되고 지역별 주차 규정 Q&A가 잠정 1순위가 됐다. #10(review-coach 최소 기획서)은 웹 UI(근거 조회 페이지)를 Must로 올리고, #9의 `pattern` 테이블 `UNIQUE(developer_id, category_id)` 제약이 자체 설계(RP-1, 같은 카테고리 내 여러 패턴 구분)와 양립하지 않는다고 지적했다. #11(주차규정봇)은 조항 번호 매칭을 이유로 Hybrid Search(BM25+Vector)와 조항 단위 청킹을 초기 선택으로 두고 "열린 위험"(데모 매력, 조례 수집 범위)을 남겼다. powercodingman의 #9(review-bot baseline + RAG 레이어 설계)는 #6에서 배제한 비공개 문서를 되살리지 않았는지, `docs/proposals/README.md` 충돌, PRD 표현 수위 세 가지를 리뷰어 판단 사항으로 요청했다.

### #6 review-bot 개인 문서 오저장 방지 (MERGED, 2026-09-07)

배경은 개인 운영 중인 review-bot 관련 문서 두 건이 `pr-review-agent-reference-design.md`가 비공개로 유지하기로 한 정보(대상 레포 실명, 환경변수명, DB 스키마, 소스 라인 참조, 배포 경로 등)를 담고 있어 팀 레포에 커밋하면 안 된다고 판단한 것이다. 배경은 확정된 임베딩 설정으로 `embed.py`를 추가하고 `CompanyDisclosureIndex.search()`를 하이브리드로 바꾸는 것이었다. 점수는 `cosine_similarity + (키워드 부분 문자열 매치 시 1.0)`이고, `min_score=0.3`은 "유상증자" 쿼리 실측(무관 ~0.16 / 같은 도메인 무관 ~0.27 / 의미 관련 ~0.33 / 키워드 포함 ~0.52+)으로 정했다. CI가 `local` extra(~2.5GB)를 설치하지 않으므로, 기본 테스트는 one-hot 가짜 임베딩으로, 실제 모델 검증은 `slow` 마커로 분리했다.

쟁점은 두 가지였다. 첫째, 같은 `search()`를 `rcept_dt` 내림차순으로 바꾼 #34와 설계가 충돌했다. 9abin은 "relevance 1차 + 약한 날짜 감쇠 항"을 제안했고, jh3779는 #34를 리베이스해 관련도 점수를 주 기준으로 유지하고 동점일 때만 `rcept_dt` 최신순으로 tie-break하는 안으로 합쳤다. 둘째, 리뷰에서 (a) 가짜 임베딩 테스트가 "키워드 vs 순수 의미" 비교를 실제로는 검증하지 못한다는 점(9abin, 비블로킹), (b) docstring의 "키워드 매치는 항상 문턱을 넘는다"는 계약이 `cos ≤ -0.7`이면 깨진다는 점(jh3779, 비블로킹; 실측상 일어날 가능성은 낮다고 명시)이 지적됐다. 두 지적의 반영 여부는 원문 불분명하다. #27 병합에 따른 리베이스로 승인이 두 번 초기화됐고, 내용 변경이 없음(7개 파일 0줄 차이)을 확인한 뒤 재승인·병합됐다.
