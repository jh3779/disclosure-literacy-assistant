# 05. 상태 머신 (State Machine)

> 2026-09-24 구현 기준. 페이지·입력 초안·전원·직전 결과는 세션 상태, 조회 기록은 앱 프로세스 메모리다.

## STATE-001 · 조회 결과

| 상태 | 조건·표시 |
| --- | --- |
| idle | 아직 조회 결과 없음 |
| loading | 유효한 입력으로 `/result`에서 조회 중. 조회 기준·스피너·경과 시간 표시 |
| result-fact | 사실 대조 결과와 맥락 확보 또는 맥락 미표시 안내 |
| result-empty | 관련 공시를 찾지 못함 |
| previous-result | 보존 결과의 종목·문장과 현재 입력이 다름 |
| error | 조회 예외를 사용자 안내로 표시 |
| sample | `NotImplementedError` 폴백, 샘플 캡션 필수 |

```text
idle / result / previous-result / error ─[유효한 입력 + 확인]→ loading
loading → result-fact / result-empty / sample / error
result ─[입력 화면에서 초안 변경]→ previous-result (직전 결과를 열 때 안내)
previous-result ─[조회 당시 입력으로 복원]→ result
error ─[재조회 성공]→ result (오류 제거)
```

`LookupResult`는 조회 당시 문장·종목 코드·종목명·카드·샘플 여부·맥락 스냅샷을 함께 보관한다.
위젯 재실행만으로 결과를 지우지 않는다. 새 조회가 시작되면 직전 결과와 오류를 정리한다.
입력이 비었거나 너무 짧을 때는 조회를 시작하지 않으므로 직전 결과가 유지된다.

`_QueryDraft`는 종목 코드·종목명·입력 문장·예시 선택을 위젯 키와 별도로 보관한다.
페이지 이동 시 Streamlit이 입력 위젯 상태를 정리해도 이 초안에서 값을 복원한다.
직전 결과의 조회 기준은 초안을 수정해도 바뀌지 않는다.

`_LookupRequest`는 조회 문장·종목·샘플 옵션의 불변 스냅샷이다. 유효한 입력을 확인하면
`_pending_lookup`에 저장하고 결과 페이지로 이동한다. 결과 페이지는 요청을 먼저 `pop`한 뒤
조회하므로 완료 후 재실행이나 직전 결과 보기에서 같은 요청을 다시 실행하지 않는다.
`_last_lookup_request`에는 실행 당시 스냅샷을 보관해 오류 화면도 초안 수정과 무관하게
실패한 조회의 종목·문장을 보여준다.

`_print_result_once`는 조회 성공 후에만 설정하고 결과의 첫 렌더에서 소비하는 표시 플래그다.
오류에서는 설정하지 않으며 재열람·일반 재실행에는 출력 애니메이션 CSS를 주입하지 않는다.
출력 연출은 조회 상태를 바꾸지 않는다. 브라우저에서 모션 축소를 요청하면 정지된 결과를 표시한다.

## STATE-002 · 이전 ClusterStats 모델

`ClusterStats`와 `ReportCard.phrase_stats`는 파이프라인 호환성을 위해 남아 있지만 화면에
렌더링하지 않는다. 이전의 “표본 N건 중 M건이 사후 이벤트로 이어짐” 상태 표시는 현행 UI
계약에서 제외한다. 맥락 지도는 `ClusterMeaning.is_reliable`을 확인하며, 매칭 실패와
신뢰도 미달 모두 이유를 안내한다. 도메인 통계를 전원 상태와 결합하지 않는다.

## STATE-003 · 입력 단말기 전원

```text
세션 첫 방문 → off
세션 첫 방문 + ?power=on → on (켜짐 연출 생략)
off ─[전원 켜기]→ on (켜짐 연출 1회)
on ─[종목·예시·문장·탭 조작 / 조회]→ on (켜짐 연출 없음)
```

- `_monitor_on`은 세션 동안 유지된다. 이번 범위에는 전원 끄기 동작이 없다.
- `_just_powered`는 켠 직후 한 번 소비하는 표시 플래그다. 다음 재실행에는 켜짐 애니메이션 CSS를 제거한다.
- on의 잔잡음·간섭 띠는 CSS 장식이다. 입력 포커스에서는 강도를 낮추며 조회 상태를 바꾸지 않는다.
- 사전과 조회 기록은 off/on 어느 상태에서도 접근 가능하다.
- 결과의 조회 기준과 샘플 여부를 숨기지 않는다. 전원 연출이 조회 결과를 바꾸지 않는다.
- 모션 축소 설정에서는 on 진입 시에도 애니메이션이 없다.

## STATE-004 · 페이지 이동

```text
/ 입력 ─[유효한 입력 + 확인]→ 요청 보관 → /result: loading
/result: loading ─[성공·빈 결과·샘플·오류]→ 같은 페이지 재실행 → 완료 화면
/result ─[다시 조회하기]→ / 입력 (초안·전원·직전 결과 유지)
/ 입력 ─[직전 결과 보기]→ /result (조회 실행 없음)
새 세션의 /result → 저장 결과 없음 안내 ─[다시 조회하기]→ / 입력
```

`st.navigation(position="hidden")`으로 두 페이지를 등록하고 `st.switch_page()`로 이동한다.
조회 로딩은 결과 페이지에서 표시한다. 대기 중 복귀 버튼과 공통 사이드바의 개발자 샘플
옵션을 비활성화해 위젯 재실행을 막는다. 완료 후 `st.rerun()`으로 대기 화면을 교체한다.
백그라운드 작업이나 영구 작업 큐는 아니다. 브라우저 종료·연결 단절로 조회가 중단되면
자동 재개를 보장하지 않는다. 세션이 유지되면 입력 화면에서 보관된 초안으로 다시 조회할 수 있다.
`/result` URL은 세션 결과를 보여주는 경로이며, 영구 저장 ID나 공유 링크가 아니다.

## STATE-005 · 메모리 조회 기록

`demo/history.py::get_history()`가 앱 프로세스별 `ResultHistory`를 공유한다. 조회 성공 시
`LookupResult`를 깊은 복사하여 `HistoryEntry(record_id, created_at, result)`로 한 번 추가한다.
시각은 UTC aware datetime, 화면에서는 한국 시각으로 표시한다. 같은 문장도 새 ID를 받는다.
잠금으로 동시 추가·읽기를 보호하며 읽을 때도 복사해 다른 세션의 수정이 원본에 번지지 않게 한다.

`MeaningSnapshot`은 조회 시 계산한 Graphviz DOT·코퍼스 범위 또는 미표시 사유다. 맥락 준비가
실패해도 이미 확보한 사실은 결과로 보관하며 맥락 안내를 저장한다. 재열람은 LLM·임베딩·통계를
호출하지 않는다. 카드 생성 자체가 실패하면 새 기록은 추가하지 않는다.

`_workspace_tab`은 활성 탭, `_history_selection`은 선택한 서류 ID다. 기록 탭이 활성일 때만
목록과 본문을 렌더링한다. 선택한 ID가 보관 상한으로 제외되었으면 최신 서류로 복구한다.
조회 기록은 초안·직전 결과·출력 연출 플래그를 바꾸지 않는다. 같은 서버의 새 세션에서도
기록이 보이지만 서버 재시작·Streamlit 캐시 삭제 시 소멸한다. 영구 저장이나 계정별 기록은 아니다.
