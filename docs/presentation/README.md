# 발표 산출물 (로컬 보관)

2026-09-29 최종발표에 쓴 슬라이드와 시연 영상을 두는 곳이다. **파일 자체는 커밋하지
않는다** — 둘 다 200MB대라 GitHub의 파일당 100MB 하드 리밋을 넘는다. `.gitignore`가
이 디렉터리를 통째로 무시하고 이 README만 예외로 둔다.

발표 내용·대본·Q&A는 `docs/final-presentation-outline.md`, 진행 현황은 `docs/WBS.md`에
있다. 이 문서는 "그 바이너리가 어디 있고 무엇인가"만 기록한다.

### 시연 영상에 담긴 흐름

한국가스공사 + 유상증자 조회 한 건을 처음부터 끝까지 보여준다. 프레임 확인 기준으로
다음이 전부 화면에 나온다.

- 입력 화면(종목 선택 + 예시 루머 3종 + 루머 문장 입력란)
- 팩트체크 결과 — **뒷받침하는 사실과 배치되는 사실이 같은 크기·같은 색으로 나란히**
  (CLAUDE.md 주의점 2 "부정/긍정 사실 동일 비중"을 화면으로 보여주는 지점)
- 참고 사실 + 근거 원문 펼침(접수번호·공시 유형·날짜 병기)
- 맥락 지도 — 회사 → 최근 표현 → 공시 유형 → 최근 비중, 예측 없는 서술형

발표 대본 4절(데모, 2분)이 이 영상을 재생하는 구간이다.

## ⚠️ 외부 공개 전 확인할 것

시연 영상 배경에 **제3자 저작물인 배경 이미지**가 그대로 찍혀 있다. 레포에서는
`chore/prepare-public-release` 브랜치가 이 이미지를 CSS 배경으로 교체했지만, 이미 녹화된
영상에는 남아 있다. 이 영상을 공개 Release·포트폴리오·외부 공유에 쓰려면 **다시 녹화하거나
해당 구간을 가려야 한다.** 내부 보관·발표 재생까지는 문제 없다.

## 공유가 필요하면

코퍼스와 같은 방식으로 GitHub Release에 올린다(`docs/DEV-SETUP.md` 8절의
`corpus-snapshot-2026-09-16` 전례). 레포에 직접 커밋하는 선택지는 없다 — 100MB 리밋에
걸린다.

```bash
gh release create presentation-2026-09-29 \
  "docs/presentation/공시 리터러시 어시스턴트 — 기술부록포함.pptx" \
  --title "최종발표 산출물 (2026-09-29)" --notes "슬라이드. 시연 영상은 저작권 확인 후 별도."
```

## 백업

이 디렉터리는 gitignore 대상이라 **git이 보호해 주지 않는다.** 레포를 다시 클론하거나
작업 트리를 정리하면 사라진다. 중요한 산출물이니 클라우드 드라이브 등에 사본을 따로
두는 걸 권한다.
