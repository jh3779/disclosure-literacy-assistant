# 디자인 리뷰 반영 — 대기·근거·모바일 검증

2026-09-23. 사용자 승인 범위: 결과 화면 디자인 리뷰 → 조회 대기·완료 흐름 개선 →
모바일·접근성 점검. 기존 CRT 입력과 밝은 출력물의 시각 방향을 유지했다.

## 리뷰 방법과 발견

`design-review`의 critique·layout·typeset·clarify·adapt·polish 지침을 적용했다.
스킬이 요구하는 독립 평가 두 건을 실시했다. A는 다른 평가 결과를 읽기 전에 화면과
소스를 검토했고, B는 별도 탭에서 모바일·접근성·스타일을 확인했다. 이후 결과를 종합했다.

- 평가 A: `/root/design_assessment_a`, 데스크톱·12초 지연·오류·왕복.
- 평가 B: `/root/design_assessment_b`, 데스크톱·320px·400px·긴 문장·키보드·계산된 스타일.
- 리뷰 도구의 `context.mjs`, `detect.mjs`, `critique-storage.mjs`, `live*.mjs`는 설치되어
  있지 않았다. 자동 detector·overlay·자동 추세 저장은 실행하지 않고 실제 Chrome과 소스로
  확인했다. 아래 수치는 자동 접근성 인증이나 모든 페이지의 종합 점수가 아니다.

평가 A의 변경 전 Nielsen 점수는 **27/40**이었다. 0~4 척도이며 모두 적용 가능한 항목이다.

| 항목 | 점수 | 주요 근거 |
| --- | --- | --- |
| 시스템 상태 가시성 | 2 | 대기가 입력 하단에 묻히고 상단은 준비 완료로 남음 |
| 현실과의 일치 | 3 | 작업 용어는 자연스럽지만 오류에 API 설정 노출 |
| 사용자 통제 | 3 | 입력 복원과 명확한 복귀 동작 |
| 일관성 | 3 | 동일 원문이 구별되지 않는 두 개의 펼침으로 반복 |
| 오류 예방 | 3 | 입력 검사 있으나 대기 중 편집·확인 UI가 계속 보임 |
| 기억 부담 감소 | 2 | 사실과 원문의 연결이 없고 조회 문장은 작은 캡션 |
| 유연성·효율 | 3 | 예시·직전 결과 지원, 중복 원문 탐색은 비효율 |
| 미학·최소주의 | 3 | 테마는 명확하지만 조회 문장을 설명에서 반복 |
| 오류 복구 | 2 | 실패한 조회 기준이 사라짐 |
| 도움말 | 3 | 예시·사전은 유용하나 사실 열 도움말 이름은 둘 다 Help |

유지할 강점은 입력과 읽기 환경의 분리, 뒷받침·배치 사실의 동일한 시각적 비중,
다시 조회할 때 종목·초안을 복원하는 동작이었다. 변경 후 총점은 새로 산정하지 않았다.

## 반영한 변경

| 우선순위·문제 | 구현 |
| --- | --- |
| P1 · 대기가 입력 아래에 묻힘 | 유효한 제출 즉시 `/result`로 이동. 조회 기준·대기 제목·설명·실제 경과 시간을 표시한 뒤 완료 화면으로 교체 |
| P1 · 사실과 원문 관계 불명확 | 사실에 근거 번호 링크 추가. 동일 섹션은 원문 한 번만 표시하고 다른 섹션은 유지 |
| P2 · 작은 조회 문장·중복 설명 | 조회 문장을 16px 일반 텍스트로 한 번만 표시. 설명 반복 제거·제목 크기 조정 |
| P2 · 오류 맥락 소실 | 실패한 종목·문장 보존, 구체적인 복귀 안내. 운영 설정 정보는 접힌 기술적 상세로 이동 |
| P2 · 제목·키보드·모바일 | H1→H2→H3 계층, 근거 포커스 표시, 주요 버튼 44px, 예시 문장 줄바꿈 |

`_LookupRequest`를 보관해 이동한 뒤 결과 페이지에서 요청을 소비하고 조회한다. 요청은 실행
전에 제거하므로 완료 후 재실행·직전 결과 열람이 중복 조회를 발생시키지 않는다. 대기 중
복귀 버튼과 개발자 샘플 옵션은 비활성화한다. 진행률이나 실제로 관측하지 않은 단계를 만들지 않는다.

원문 중복 판단은 `DisclosureSection`의 모든 필드가 같은 경우에만 적용한다. 접수번호만으로
합치지 않으므로 같은 공시 안의 다른 절이 사라지지 않는다. 한 원문을 공유하는 두 사실의
링크는 같은 번호를 가리킨다. 원문 위치로 이동한 뒤 Tab·Enter로 펼칠 수 있다.

## 실제 Chrome 확인

`tests/fixtures/terminal_preview.py`의 고정 데이터를 임시 서버에서 사용했다. 대기 확인에만
임시 복사본의 `build_report`에 12초 지연을 넣었다. 제품 코드에는 인위적인 지연이 없다.
실제 DART·LLM 호출은 사용하지 않았다.

| 확인 항목 | 결과 |
| --- | --- |
| 제출 후 대기 | 처리 완료 전 URL `/result`, H1 “공시 대조 중”, 조회 기준·지연 안내·비활성 복귀 버튼, CRT 없음 |
| 실제 시간 | native `role=status` 스피너와 6.1 seconds 표시 관찰 |
| 완료 | 같은 경로에서 “공시 대조 결과”로 교체, 복귀 버튼 활성화 |
| 원문 연결 | 두 사실이 근거 1 공유, 펼침 한 개. 링크→앵커→Tab→원문 펼침→Enter 동작 확인 |
| 제목 탐색 | 페이지 H1, 사실 대조·맥락 H2, 사실 그룹·근거 H3 확인 |
| 오류·복귀 | 오류에도 종목·문장 유지, 기술적 상세 기본 닫힘, 입력으로 복귀 시 원문 복원 |
| 400 × 860 | 대기·완료·오류 확인, 문서 너비 400px, 결과 두 열은 세로 배치 |
| 320 × 860 | 긴 문장과 결과 확인, 문서 너비 320px, 가로 넘침 없음 |
| 모바일 입력 | 확인 버튼·종목 지우기·펼치기 44px 높이, 예시 칩 54.8px 높이로 두 줄 전체 표시 |
| 최종 콘솔 | 새 검증 탭의 warn/error 0건 |

320px에서 같은 긴 조회 문장 기준 첫 사실 시작 위치는 변경 전 **y=784.3px**, 최종
**y=681.4px**로 약 103px 앞당겨졌다. 조회 문장을 14px 캡션에서 16px 본문으로 키우면서
중복 설명을 없앤 결과다. 쿼리의 내부 span까지 `word-break: keep-all`을 적용해 어절을
보존하고, 긴 단일 토큰은 `overflow-wrap: anywhere`로 넘침을 방지한다.

리뷰에서 계산한 기본색 대비는 종이 본문 13.65:1, 캡션 5.45:1, DART 링크 6.21:1이었다.
이 패스에서 해당 색 조합은 바꾸지 않았다. CRT 장식 합성 픽셀과 모든 상호작용 상태에 대한
대비 검사를 완료했다는 의미는 아니다. 서버 재시작 시 이전 탭에는 연결 경고가 있었고,
재시작 후 새 탭의 최종 검사에는 경고·오류가 없었다. 임시 viewport는 확인 후 복원했다.

## 범위와 한계

- 결과와 입력은 세션에만 보관한다. 조회는 백그라운드 영구 작업이 아니며 브라우저 종료나
  연결 단절 후 자동 재개를 보장하지 않는다. `/result`는 저장·공유 링크가 아니다.
- Safari, 실제 모바일 기기, 스크린리더 실제 낭독, 200% 확대는 이번에 확인하지 않았다.
- CRT 모션 축소 규칙은 유지했다. 이번 패스에서 OS 모션 설정을 다시 검증하지 않았다.
- 실제 LLM 품질·응답시간은 다시 측정하지 않았다. 임시 고정 데이터는 제품 정확도의 증거가 아니다.
- `코퍼스` 등 남은 도메인 용어의 전체 문구 정비는 이번 다섯 우선 개선 범위에 포함하지 않았다.
- 기존 8501·8504 조회 세션을 유지하고 최신 본 앱 미리보기는 8506에서 제공한다.
