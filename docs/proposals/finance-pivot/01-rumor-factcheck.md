# 테마주 루머 팩트체커 — 기획서

> **상태**: 제안 단계(2026-09-09) — 금융 도메인 피벗 후보 중 하나. [공시 국어사전](02-disclosure-dictionary.md)과
> 별개 기능으로 검토한 버전이며, [통합안](03-integrated-proposal.md)에서는 이 기능이 팩트체크 엔진(L2a)으로 들어간다.
> 이 문서는 통합 여부와 무관하게 이 기능 단독의 문제정의·리스크를 비교 검토할 수 있도록 남겨둔다.
>
> 🔒 **기준문서(잠금, 과거 검토 기록)** — 채택 시점 스냅샷이라 사실 정정 외에는 내용을 고치지
> 않는다. AI 에이전트는 사용자 명시 요청 없이 수정하지 않는다 (`../../../CONTRIBUTING.md` 규칙 6).

## 1. 배경 및 문제정의

커뮤니티·유튜브·오픈채팅에서 "OO, 초전도체/양자컴/비만치료제 관련 수혜주" 같은 테마주 루머가 빠르게
퍼진다. 개인투자자가 이를 직접 검증하려면 DART 전자공시시스템에서 해당 종목의 공시를 뒤져야 하는데,
전문검색 UI가 불친절하고 공시 서식 구조(MOU/유상증자/최대주주변경 등)를 모르면 어떤 항목을 봐야
하는지 판단이 어렵다. 결과적으로 검증 없이 루머가 확산되고, 뒤늦게 손실을 본 투자자들이 "이거
미리 봤어야 했다"며 사후에 공유하는 패턴이 반복된다.

## 2. 타겟 사용자

- 커뮤니티/유튜브에서 테마주 루머를 접한 개인투자자
- "이 루머가 진짜인지" 몇 분 안에 1차 확인하고 싶은 사람

## 3. 핵심 기능

1. 루머 텍스트 입력 (예: "OO, 초전도체 관련 수혜 기대")
2. 종목명/핵심 키워드 자동 추출
3. DART 전문검색으로 해당 종목의 최근 공시에서 그 키워드가 실제로 등장하는지 대조
4. 결과는 **사실 나열만**: "MOU 공시 1건(구속력 조항 없음, 2026-08-12)", "매출 인식 0원(최근
   분기보고서 기준)", "최대주주 지분 매도 2회(최근 3개월)" — 긍정·부정 사실을 동일 비중으로
   기계적으로 나열한다
5. 근거가 된 공시 원문 링크를 첨부하고, 최종 판단은 사용자 몫으로 남긴다

## 4. 데이터 & 파이프라인

- **DART OpenAPI** (원문 zip/XML, 재무정보 API) — 무료·즉시 발급 확인됨(2026-09-09 자체 리서치)
- KIND(자율공시), 공매도·지분공시
- 공시 원문 → 서식 유형별 섹션 청킹(표준 항목 구조 활용, narrative_qa의 챕터 경계 청킹보다
  단순·명확함) → 임베딩 → 종목코드/공시일자/서식유형 메타와 결합한 하이브리드 검색

## 5. RAG 아키텍처 개요

일반 QA가 아니라 **"주장 → 근거 검색 → 대조"** 구조(claim verification)다. 팀이 이전에 구현한
narrative_qa 프로젝트의 `qa/chain.py` guard(groundedness 체크) 패턴을 거의 그대로 재사용할 수
있다 — "루머 문장이 실제 공시 사실로 뒷받침되는가"를 groundedness 체크처럼 구현한다.

## 6. 규제 리스크 및 대응

자본시장법상 유사투자자문업(불특정 다수를 상대로 특정 금융투자상품에 대한 투자판단 자문)에
해당하지 않도록 다음을 지킨다:

- 매수/매도 추천, 목표가, 수익률 예측을 **일절 출력하지 않는다**
- "루머 신빙성 신호등"처럼 종합 판단으로 읽히는 등급·점수는 **배제**한다 — 개별 사실 나열까지만
- 부정적 사실만 골라 나열하면 암묵적 매도 시그널로 읽힐 수 있어, UI 레벨에서 긍정/부정 사실을
  동일 비중으로 노출하도록 강제한다

## 7. 경쟁 서비스 비교 (2026-09-09 WebSearch 기준)

- 한경 유레카: "공시 분석을 통해 투자할 가치가 있는 종목을 발굴" — 이 기획과 방향이 반대(종목
  발굴 vs 루머 검증)라 성격이 다르다
- "루머를 입력하면 팩트체크"하는 직접 경쟁 서비스는 특정하지 못했다 — 다만 존재하지 않는다는
  증명은 아니므로, 실제 착수 전 재검증이 필요하다

## 8. 평가 방법

과거 실제 테마주 루머 사례(커뮤니티 아카이브·뉴스 기사에서 수집)를 20~30건 gold set으로 구성
→ 팩트체크 결과가 실제 사후 공시와 일치하는지 정밀도·재현율로 측정한다.

## 9. 리스크와 완화

| 리스크 | 완화 |
| --- | --- |
| 부정적 사실 나열이 암묵적 매도 시그널로 읽힘 | 긍정/부정 사실 동일 비중 노출을 UI 레벨에서 강제 |
| 루머 원문에서 종목/키워드 추출 실패(비정형 텍스트) | LLM 기반 키워드 추출 + 실패 시 사용자에게 재입력 요청 |
| DART 검색 커버리지 누락(비상장·코넥스 등) | 스코프를 코스피·코스닥 상장사로 한정 |

## 11. Phase 및 마일스톤

- **Phase 1 — 기반 구축** (A): DART 원문 수집·인덱싱. 완료 기준: 종목 하나 기준 최근 공시 검색 가능
- **Phase 2 — 엔진 개발** (B 주도, C 병행): B가 claim verification 로직 구현, C는 동시에 과거
  루머 사례 20~30건 gold set 수집·검수. 완료 기준: 엔진 단위 테스트 통과 + gold set 확보
- **Phase 3 — 통합/평가** (C 주도): 데모 UI 조립, gold set 대비 정밀도·재현율 측정. 완료 기준:
  엔드투엔드 데모 동작 + 평가 결과표 완성
