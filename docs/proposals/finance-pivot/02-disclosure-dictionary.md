# 공시 국어사전 — IR 화법 번역기 기획서

> **상태**: 제안 단계(2026-09-09) — 금융 도메인 피벗 후보 중 하나. [테마주 루머 팩트체커](01-rumor-factcheck.md)와
> 별개 기능으로 검토한 버전이며, [통합안](03-integrated-proposal.md)에서는 이 기능이 화법통계 엔진(L2b)으로
> 팩트체크 결과의 자동 주석 레이어로 들어간다. 이 문서는 통합 여부와 무관하게 이 기능 단독의 문제정의·
> 리스크를 비교 검토할 수 있도록 남겨둔다.
>
> 🔒 **기준문서(잠금, 과거 검토 기록)** — 채택 시점 스냅샷이라 사실 정정 외에는 내용을 고치지
> 않는다. AI 에이전트는 사용자 명시 요청 없이 수정하지 않는다 (`../../../CONTRIBUTING.md` 규칙 6).

## 1. 배경 및 문제정의

"선제적 재무구조 개선", "중장기 성장 동력 확보" 같은 상투적 공시·IR 문구가 실제로 무엇을
의미하는지 개인투자자는 경험적으로만 짐작한다. 기존에는 "공시줍줍"(비즈워치 뉴스레터, 기자가
매일 공시를 골라 수작업으로 해설) 같은 **편집형** 서비스만 존재했고, 사용자가 임의의 문장을
넣어 즉시 통계를 확인하는 셀프서비스 도구는 없다.

## 2. 타겟 사용자

- 공시·IR 자료를 읽지만 상투 화법의 실제 함의를 모르는 개인투자자
- "이 표현, 과거엔 보통 무슨 일로 이어졌지?"를 즉시 확인하고 싶은 사람

## 3. 핵심 기능

1. 공시·보도자료 문장 입력 (또는 최근 공시에서 후보 문장 자동 추출)
2. 유사 표현이 과거 공시에서 쓰인 사례를 벡터 검색으로 매칭
3. 매칭된 과거 사례들의 **사후 행동 통계**를 집계해 제시: 예) "이 표현 이후 12건 중 9건이 3개월
   내 유상증자로 이어짐" — 이 정량 통계 산출이 기존 편집형 서비스와의 핵심 차별화 지점
4. 사례 원문 링크 첨부, 개별 종목명 노출은 최소화(집계 통계 우선)

## 4. 데이터 & 파이프라인

- **DART OpenAPI** (원문 zip/XML, 재무정보 API) — 무료·즉시 발급 확인됨(2026-09-09 자체 리서치)
- 과거 공시 텍스트에서 유사 상투구 클러스터링(임베딩 유사도 기반)
- 각 클러스터에 대해 "그 이후 N개월 내 실제 발생한 후속 이벤트"(유상증자·인력감축 관련 후속
  공시 등)를 DART 후속 공시로 라벨링 — **이 라벨링이 팀의 핵심 구현 작업**이며, narrative_qa
  프로젝트의 gold set 수동 검수 작업과 성격이 같다(자동 초안 + 전원 수동 검수)

## 5. RAG 아키텍처 개요

순수 QA가 아니라 **"표현 클러스터링 + 사후 이벤트 라벨링"** 파이프라인이다. 검색 시점에는
입력 문장 → 가장 가까운 클러스터 매칭 → 사전 계산된 통계를 반환하는 구조로, 매 요청마다 LLM을
호출하지 않고 사전 계산된 캐시를 조회하는 방식에 가깝다(비용 관리에 유리).

## 6. 규제 리스크 및 대응

셋 중 가장 낮은 리스크로 평가한다. "이 표현이 역사적으로 무엇을 의미했나"는 특정 시점·특정
종목에 대한 투자판단이 아니라 **언어 패턴에 대한 통계적 사실**이라 자본시장법상 유사투자자문업
경계가 뚜렷하다. 다만:

- 개별 사례를 인용할 때 "이 회사가 그렇다"는 인상을 주지 않도록 **집계 통계를 우선 노출**하고
  개별 종목명은 클릭 시에만 보이도록 설계한다
- 표본 수가 적은 클러스터(예: 3건 이하)는 통계적으로 유의하지 않다고 명시한다

## 7. 경쟁 서비스 비교 (2026-09-09 WebSearch/WebFetch 기준)

- **공시줍줍**(비즈워치 뉴스레터, 책으로도 출판): 기자가 매일 공시 중 투자자에게 필요한 것만
  선별해 정성적으로 해설 — **사람이 수작업으로 편집**하는 서비스이고, 사용자가 임의 문장을 넣어
  정량 통계를 받는 자동화 도구는 아니다. 차별화 지점: 자동화·셀프서비스·정량 통계
- 그 외 직접 경쟁 서비스는 특정하지 못함(2026-09-09 기준, 재검증 필요)

## 8. 평가 방법

라벨링된 클러스터-통계가 실제로 통계적으로 유의한지(최소 표본 수 기준 설정), 새 문장이 올바른
클러스터에 매칭되는지 사람 검수로 확인한다.

## 9. 리스크와 완화

| 리스크 | 완화 |
| --- | --- |
| 개별 종목명 노출로 암묵적 종목 판단처럼 읽힘 | 집계 통계 우선, 개별 종목명은 클릭 시에만 |
| 표본 부족 클러스터의 통계 왜곡 | 최소 표본 수 미달 시 "통계적으로 유의하지 않음" 명시 |
| 클러스터링 품질(유사 문구인데 다른 클러스터로 분리) | 임베딩 모델 검증 + 사람 검수 fallback |
